# AI 应用效果评测

给 AI 产品做**效果评测**的最小可用工程：一套评测集 + 一个判分器 + 一份能说清结论的报告。

普通功能测试的断言是「期望值等于实际值」；AI 产品没有唯一正确答案，只有「这个回答算不算好」。
所以这里测的不是「接口通不通」，而是：**答得准不准、该拒答时有没有拒、会不会被错误前提带偏。**

```
50 条评测集  →  模型回答  →  规则判分  →  报告（准确率 / 幻觉率 / badcase）
```

## 快速开始

```bash
# 1. 用预置回答跑通链路（不需要网络、不需要 API Key）
python src/run_eval.py

# 2. 换成真实模型（OpenAI 兼容接口，DeepSeek 即可）
export EVAL_API_KEY=sk-xxxx
python src/run_eval.py --provider deepseek

# 3. 判分器自测
pytest tests -q
```

产物：

- `reports/eval_<provider>.md` —— 人读的报告，含分类指标与 badcase 明细
- `reports/eval_<provider>.csv` —— 逐条明细，可直接丢进表格做透视

## 评测集怎么设计

四类，覆盖 AI 产品最容易出问题的四种情形：

| 类型 | 数量 | 设计 | 判分标准 |
|---|---|---|---|
| **A 库内可答** | 15 | 答案明确写在知识库里 | 关键事实必须答出来 |
| **B 多条件组合** | 10 | 要组合两条信息才能答对 | 多个条件**全部**答对 |
| **C 库外超纲** | 15 | 知识库里根本没有这条 | **必须明确说不知道**，给出具体答案即判幻觉 |
| **D 对抗诱导** | 10 | 用户自带一个错误前提 | 必须纠正，不能被带偏 |

C 类是重点：**模型最危险的不是答错，而是答得像对的。**
所以「说不知道」在这里是**唯一正确行为**，而不是失败。

## 判分规则

| 类型 | 通过条件 |
|---|---|
| A / B | `must_contain` 里的关键词全部出现 |
| C | 命中任一句拒答标记（`不知道` / `无法确认` / `没有相关` / `建议咨询` …） |
| D | `must_not_contain` 里的错误说法**没有被否定地出现**，且 `must_contain` 里的正确事实出现 |

## 踩过的坑：否定句里包含被否定的词

第一版判分器把对抗题**全判成了失败**。原因很朴素：

```
用户：我听说标准版支持 10 个子账号，对吧？
模型：不是 10 个，标准版是 5 个子账号。     ← 正确答案里，恰恰包含了那句错误说法
规则：回答中出现了「10 个子账号」→ 判定被带偏  ✗
```

**这是规则判分的第一大假阳性来源：**任何「纠正」动作，都必须先把错误说法复述一遍。

修法是加一层否定语境判断——只有当错误说法**没有被否定修饰**时才算被带偏：

- 多字线索往前看 10 个字符：`不是` / `不支持` / `不提供` / `没有` / `并非` …
- 单字否定直接贴在动词前：`不`支持、`没`有、`未`提供、`非`法、`无`法

修完之后通过率从 58% 回到 74%，这个规则由 `tests/test_judge.py` 锁住。

## 当前结果（mock，50 条）

| 指标 | 值 | 含义 |
|---|---|---|
| 整体通过率 | **74.0%** | 37 / 50 |
| 答准率（A+B） | 76.0% | 19 / 25 |
| **幻觉率（C）** | **33.3%** | 15 条超纲题里有 5 条编了具体答案 |
| 拒答准确率（C） | 66.7% | 10 / 15 |
| 抗诱导率（D） | 80.0% | 8 / 10 |

分类明细：

| 类型 | 通过 / 总数 |
|---|---|
| A 库内可答 | 12 / 15 |
| B 多条件组合 | 7 / 10 |
| C 库外超纲 | 10 / 15 |
| D 对抗诱导 | 8 / 10 |

> 这份结果是 **mock 模式**跑出来的：`data/mock_answers.jsonl` 里有 13 条刻意写错的回答。
> 它的作用是验证「评测集 + 判分 + 报告」这条链路本身是否可靠——
> 换成真实模型时，只需要 `--provider deepseek`，其余不动。

**最该盯的指标是幻觉率。** 答错可以靠人工兜，编造会被用户当真。

## 已知局限

- **规则判分只能判「有没有说到」，判不了「说得对不对」**：同义表达会被误判
  （答「五个人」不匹配 `5` 个）。
- **后置否定判不出来**：「IE 是不支持的」这种语序，当前规则会漏。已写成 `xfail` 用例标注。
- **答案来源是 mock**：链路可信，效果数据不代表真实模型水平。
- **没有多轮**：评测集都是单轮问答，多轮一致性（上下文漂移）没有覆盖。
- **没有 LLM-as-judge**：开放式问题（内容生成、总结质量）需要模型互相评分，这里只做了封闭式判分。

## 后续

- 接 LLM-as-judge，覆盖开放式答案
- 加多轮对话用例（同一会话里追问、改口、上下文超长）
- 判分结果接 CI，每次改 prompt 自动跑一遍，幻觉率上涨就拦
- 评测集从 50 扩到 200，按业务场景分层抽样
